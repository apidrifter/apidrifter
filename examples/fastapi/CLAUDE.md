# FastAPI example

Spec: generated by FastAPI from the annotations in `main.py`, served at
`http://localhost:8000/openapi.json`; `python export_spec.py > openapi.json` writes it to a
file. Start the app with `uvicorn main:app --port 8000` inside the virtualenv.

## API contract checks

When you add or change an HTTP endpoint or a Pydantic model that feeds the OpenAPI document,
verify the implementation against the spec before opening a pull request:

1. Start the service locally and note its port.
2. Run `npx -y apidrifter plan http://localhost:8000/openapi.json --out plan.json` to see
   which parameter and body values the engine cannot infer, and write a filled plan with
   realistic values from the codebase.
3. Run `npx -y apidrifter run http://localhost:8000/openapi.json --base-url http://localhost:8000 --plan filled.json --format markdown`.
   Plain http:// is only allowed for localhost. Never put real credentials in the plan, the
   command line or the report; use `--bearer-env VAR` for tokens.
4. For each finding, decide which side is the source of truth: the spec (fix the
   implementation) or the implementation (fix the model or annotation the spec is generated
   from). Do not loosen the model just to make the report clean.
5. Fix and rerun until there are no findings at or above the fail level, then paste the
   Markdown report into the pull request description.

When only models or annotations changed, regenerate the snapshot with
`python export_spec.py > openapi.json`, then run
`npx -y apidrifter breaking <old openapi.json> openapi.json` and put the changelog
(`npx -y apidrifter changelog <old openapi.json> openapi.json`) in the pull request.
