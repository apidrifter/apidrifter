# NestJS example

Spec: generated by `@nestjs/swagger` from the decorators in `src/`, served at
`http://localhost:3000/openapi.json`; `npm run spec` writes it to `openapi.json`. Start the
app with `npm start` (compiles with tsc first); it listens on port 3000.

## API contract checks

When you add or change an HTTP endpoint, a controller or a DTO that feeds the OpenAPI
document, verify the implementation against the spec before opening a pull request:

1. Start the service locally and note its port.
2. Run `npx -y apidrifter plan http://localhost:3000/openapi.json --out plan.json` to see
   which parameter and body values the engine cannot infer, and write a filled plan with
   realistic values from the codebase.
3. Run `npx -y apidrifter run http://localhost:3000/openapi.json --base-url http://localhost:3000 --plan filled.json --format markdown`.
   Plain http:// is only allowed for localhost. Never put real credentials in the plan, the
   command line or the report; use `--bearer-env VAR` for tokens.
4. For each finding, decide which side is the source of truth: the spec (fix the
   implementation) or the implementation (fix the DTO or decorator the spec is generated
   from). Do not loosen the DTO just to make the report clean.
5. Fix and rerun until there are no findings at or above the fail level, then paste the
   Markdown report into the pull request description.

When only DTOs or decorators changed, regenerate the snapshot with `npm run spec`, then run
`npx -y apidrifter breaking <old openapi.json> openapi.json` and put the changelog
(`npx -y apidrifter changelog <old openapi.json> openapi.json`) in the pull request.
